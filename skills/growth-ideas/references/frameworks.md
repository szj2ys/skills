# 增长创意框架详细参考

三套正交扫描框架的完整检查清单和验证模板。

## A. 产品改进框架（AARRR + 摩擦点）

| 检查点 | 问什么 | 典型想法来源 |
|---|---|---|
| Acquisition | 用户怎么来的？来源分布？哪个渠道在萎缩？ | 新渠道测试、landing page 优化 |
| Activation | 新用户首次核心行为是什么？完成率多少？ | onboarding 简化、aha moment 前置 |
| Retention | 7日/30日留存多少？流失前最后做了什么？ | 邮件/推送召回、习惯养成机制 |
| Revenue | 付费转化率？客单价？升级路径？ | 定价实验、捆绑销售、阶梯定价 |
| Referral | 有没有 NPS？用户主动推荐率？ | 裂变机制、邀请奖励、社交证明 |

额外视角：
- **被低估的功能**：现有功能中用户高频使用但未被宣传的 → 可能是核心卖点
- **用户反馈热区**：统计用户抱怨/请求的关键词 → 直接转化成功能需求

## B. 盈利策略框架

| 策略 | 适用条件 | 验证方式 |
|---|---|---|
| 免费增值 (Freemium) | 有清晰的高级功能边界 | 分析免费→付费转化漏斗 |
| 用量计费 (Usage-based) | 产品价值与用户消耗正相关 | 分析用户使用量分布 |
| 席位/团队定价 (Seat-based) | B2B、有协作场景 | 看单用户 vs 团队用户占比 |
| API/平台化 | 有开发者或集成需求 | 统计 API 调用量、集成请求 |
| 增值服务 (Upsell) | 有高频使用 + 低 ARPU | 分析付费用户升级意愿 |
| 数据/内容变现 | 积累的数据/内容有外部价值 | 看数据资产密度 |
| 合作伙伴/白标 (White-label) | 产品可嵌入第三方 | 统计 OEM 或集成咨询 |
| 咨询/专业服务 | 复杂产品 + 大客户 | 看支持工单中「能不能帮忙」占比 |

额外检查：当前定价是否「锚定错误」——定价太低导致用户轻视产品价值，或太高导致转化崩盘。

## C. 营销获客框架（内容-渠道-转化）

| 维度 | 检查清单 | 想法产出方向 |
|---|---|---|
| 内容 | 有没有 SEO 博客/教程/案例？有没有用户成功案例？有没有比较页面（vs 竞品）？ | 内容缺口 = 自然流量机会 |
| 渠道 | 目前在哪些渠道？每个渠道的 CAC 和 LTV？有没有完全没试过的渠道？ | 渠道扩张、渠道优化 |
| 转化 | 从 impressions 到付费的每一步转化率？最大 leak 在哪一步？ | 转化优化、landing page 测试 |

额外视角：
- **口碑杠杆**：找到最满意的那批用户，放大他们的声音
- **社区/生态**：用户之间有没有交流需求？建社群、论坛、模板市场

## 信息蒸馏清单

缺 3 项以上不进入 Phase 2。

| 信息维度 | 查什么 | 为什么必须 |
|---|---|---|
| 产品定位 | 做什么、为谁做、解决什么痛 | 决定想法的边界 |
| 用户画像 | 谁在付费、谁在流失、谁在活跃 | 找到付费意愿最高的 segment |
| 数据现状 | 流量、转化、留存、ARPU、CAC | 量化杠杆点 |
| 现有功能 | 核心功能列表、使用频率分布 | 发现被低估的 feature |
| 竞品生态 | 竞品在做什么、不做什么、用户骂什么 | 找到差异化空隙 |
| 已有尝试 | 之前试过什么、什么失败了、为什么 | 避免重复踩坑 |
| 资源约束 | 时间、预算、团队、技术栈 | 过滤不可行的方案 |

信息收集方式：
- 有代码库：扫描 README、产品文档、分析埋点代码、定价配置
- 有数据：请求用户贴关键数字或提供 dashboard 截图
- 有竞品：快速调研 2-3 个核心竞品的公开信息
- 什么都没有：用 ≤5 个结构化问题一次性补齐

## ICE 评分标准

- **Impact (1-5)**: 对收入/增长/留存的预期影响
- **Confidence (1-5)**: 有多大把握（有数据 = 5，直觉 = 1）
- **Ease (1-5)**: 实施难度（1天 = 5，1月 = 1）

总分 = Impact × Confidence × Ease。只保留前 10。
