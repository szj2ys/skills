# Growth Ideas — 增长创意引擎

从用户已有的数据、反馈、竞品盲区里蒸馏出可验证的增长想法，不凭空给通用建议。用三套正交框架交叉扫描产出 15-30 个想法，ICE 排序保留前 10，每个带 ≤2 周的低成本验证路径。

## 核心理念

- **想法是发现出来的，不是创造出来的。** 99% 的好主意藏在用户已有的信息里。
- **没有框架的发散是浪费。** 给框架，用户自己能产出 1000 个想法。
- **想法不值钱，可验证的想法才值钱。** 每个想法必须带验证路径。

## 工作流

### Phase 1: 信息蒸馏

不问不查不凭空。用户没主动提供以下信息时，先通过提问或代码/数据扫描补齐。缺 3 项以上不进入 Phase 2。

扫描维度（产品定位、用户画像、数据现状、现有功能、竞品生态、已有尝试、资源约束）详见 [references/frameworks.md](references/frameworks.md) 的「信息蒸馏清单」。

**信息收集方式**:
- 有代码库：扫描 README、产品文档、埋点代码、定价配置
- 有数据：请用户贴关键数字或 dashboard 截图
- 有竞品：快速调研 2-3 个核心竞品公开信息
- 什么都没有：用 ≤5 个结构化问题一次性补齐

### Phase 2: 三维创意发散

用三套正交框架交叉扫描，每套产 5-10 个想法，总计 15-30 个：

- **A. 产品改进**：AARRR + 用户旅程摩擦点
- **B. 盈利策略**：价值阶梯 + 定价心理学（Freemium / Usage / Seat / API / Upsell / 数据变现 / 白标 / 咨询）
- **C. 营销获客**：内容-渠道-转化 三角 + 口碑杠杆 + 社区/生态

每套框架的完整检查清单和典型想法来源见 [references/frameworks.md](references/frameworks.md)。

### Phase 3: ICE 优先级排序

对所有想法打 ICE 分（Impact × Confidence × Ease，1-5），只保留前 10。

评分标准详见 [references/frameworks.md](references/frameworks.md) 的「ICE 评分标准」。

### Phase 4: 输出与验证路径

对 Top 10 想法每个必须附带：假设、ICE 总分、具体且 ≤2 周的验证方法、失败止损条件、今天能做的第一件事。

完整输出模板见 [references/frameworks.md](references/frameworks.md) 的「输出模板」。

## 自检清单（发出前必须过）

1. 信息维度覆盖 ≥4 项？缺项是否标了「假设，未验证」？
2. 想法是否都从用户**已有信息**蒸馏，不是通用建议？
3. 每个想法是否有**具体的、低成本、≤2 周**的验证方法？
4. ICE 评分有无主观偏袒（比如全打 5 分）？
5. 有没有至少一个「如果验证失败」的止损条件？
6. 输出是否 ≤4000 字符？超了就把完整创意矩阵放附录，正文只留 Top 10。
