# Site Scale — 从千刀到万刀的放大决策

第一阶段的使命是证明"需求 → 页面 → 流量 → 收入"能接起来；到了月入千刀，才有条件挑更大的市场。**放大不是把没跑通的东西投更多钱，而是把已经跑通的流程再跑一遍。**

## 阶段纪律（先对表，再决策）

| 当前状态 | 允许的动作 | 禁止的动作 |
|---|---|---|
| 0 → 第一美元 | 小闭环验证（走 site-niche-loop） | 挑大市场、想万刀 |
| 第一美元 → 千刀 | 重复已验证闭环，积累资产 | 挑大市场、投广告 |
| 千刀 → 万刀 | 选路径 A 或 B 放大 | 跳过研究直接做大词 |
| 有自然流量 + 付费后 | 才逐步尝试投放 | 自然流量没跑通就投放 |

## 路径决策：A 多站复制 vs B 大词突破

| | 路径 A：多站复制 | 路径 B：大词突破 |
|---|---|---|
| 做法 | 继续做已验证的类型，多做几个能到千刀的站 | 找搜索量更大、商业价值更高的词，让一个站跨到万刀 |
| 适合 | 当前模式可复制、找词来源充足 | 已清楚一个产品需要哪些页面和数据，敢啃更大竞争 |
| 风险 | 单站天花板不变，靠数量堆 | 竞争更强，周期更长 |

两条路不互斥；先让用户说清自己的时间、精力和风险偏好，再给建议。无论选哪条，都是把前面跑通的页面、外链、排名流程**原样再用一遍**。

## 大需求研究清单（路径 B 必做）

选大词时，关键词本身不够，必须补齐四项商业研究：

1. **收入榜单**：这个市场里谁在赚钱？看已被验证的产品。
2. **用户为什么付钱**：付费解决的具体问题是什么。
3. **哪个功能促成付费**：决定页面要把哪个功能做深、放前。
4. **收费模式**：订阅还是一次性？决定页面要引导的动作和留存设计。

四项都有答案才动手；缺项就标注"假设，未验证"并给出补齐方式。

## 投放纪律（自然流量和付费出现之后才做）

1. **先验证两层**：广告能不能带来注册和使用 → 这些用户会不会付费。哪一层不通，先修哪一层。
2. **搜索用户和广告用户必须分开统计**：搜索用户带着明确问题来，广告用户可能只是被素材吸引，两批人的注册和付费表现不一样。**混成一个数字，就判断不了页面到底有没有改善。**
3. **按流失点定点修复**：看操作回放和每步转化数据，用户在哪一步离开，就回到那一步改：

| 流失现象 | 修什么 |
|---|---|
| 第一次结果出来太慢 | 等待体验 |
| 用过功能却没订阅 | 额度、价格、信任感 |
| 到支付页离开 | 付款方式、页面说明 |

逐步漏斗诊断的系统方法引用 `pm-1-funnel-diagnostic`，不要在本 skill 里重复展开。

## 输出模板

```markdown
### 📈 放大决策: [站名]

#### 1. 阶段对表
- 当前状态: [第X美元 / 月入X刀 / 是否有自然付费]
- 允许动作范围: [按阶段纪律表]

#### 2. 路径建议
- 推荐路径: [A 多站复制 / B 大词突破]
- 理由: [结合用户的时间、精力、已有资产]

#### 3. 大需求研究（路径 B 时必填）
- 收入榜单: [谁在赚钱]
- 付钱动机: [用户为什么付钱]
- 促成付费的功能: [哪个]
- 收费模式: [订阅 / 一次性]
- 缺项: [无 / 列出假设及补齐方式]

#### 4. 投放计划（仅在已有自然流量+付费时）
- 验证顺序: [注册使用 → 付费]
- 分流统计: [搜索/广告分开]
- 首个观察的流失点: [哪一步]
```

## 自检清单（发出前必须过）

1. 是否先做了阶段对表？千刀之前是否拦住了"挑大市场/投广告"的冲动？
2. 路径建议是否结合了用户自己的资源和偏好，而不是默认推大词？
3. 路径 B 的四项商业研究是否齐全？缺项是否标注了？
4. 投放建议是否以"已有自然流量和付费"为前提？
5. 是否明确了搜索/广告用户分开统计？
6. 漏斗诊断是否引用 `pm-1-funnel-diagnostic`，没有在本 skill 内重写？
