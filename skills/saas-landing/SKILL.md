# SaaS Landing

三条原则，其他一切为它们让路：

1. **第一屏三问**：用户 5 秒内必须明白——输入什么、得到什么、为什么比别处快。标题说结果，副标题说输入和输出，CTA 指向转化动作；最好的第一屏是让用户当场试。答不出三问就重写。
2. **v1 只验证三件事**：有人来、有人用、有人愿意留邮箱或付款。全页只设一个主转化动作（留邮箱 / 试用 / 付款，按产品阶段三选一），所有 CTA 都指向它。
3. **看起来贵，靠克制不靠堆砌**：配色收敛、字体层级清晰、留白充足、用真实截图而非假 mockup、文案具体不浮夸、移动端不破。
4. **最好在最合适的时机，弹出优惠弹窗还是什么，把用户的注意力就吸引住**
5. **检测用户主动关闭 landing page的行为(如快捷键关闭所有网站)，必须要有挽留的措施**，优化用户的跳出率
6. **要对用户善意引导**，不要让用户在 landing page上迷路，必须要有清晰的导航和引导措施

分析已有页面时，输出的问题清单每条必须带解决方案，不只指出问题。

重构已有页面时，先量再判：用 `web-audit` 跑一遍真实浏览器测量（对比度、触控目标、LCP/CLS、传输体积、SSR 与 hydrate 后的内容差异、断网表现），再写方案。凭感觉写的"这里对比度偏低"会被争论，`--fg-3 在 --surface 上 3.1:1，低于 4.5:1` 不会。数据也会保护你已经做对的部分——比如对比度全过、CLS 为 0，这些要写明"不许回退"。
没有真实用户数据就不要造社会证明：没有客户就删掉 testimonial、logo 墙和"已有 N 位用户"，用可当场验证的能力（样本试听、格式支持、删除承诺）替代。
最值得做的是那些有明确付费理由的小产品。真正的闷声发财产品，是离用户的具体痛点、具体收 益、具体付款动作最近的

真正适合小团队的路径不是复制一个大产品，而是把它缩小到一个更具体的人群、更具体的问题、更具体的付费场景。

创业者不要只问：这个产品用了什么技术？
更应该问：用户为什么现在就愿意付钱？ 我能不能把这个付款理由，缩小到一个更具体的人群和场景里？

范围裁决只有一条标准：是否直接服务上面三件事？服务就做，不服务就推迟——博客、多语言、用户后台、团队页、案例、动画炫技，默认全部推迟。核心功能必须真的可用，宁可只有一个能跑的功能，不要十个半成品。
