# Stage 0 · 头脑风暴（打地基，与用户对话）

**目的**：在动笔之前，把四件事与用户一起定下来：**选题、角度、目标读者、素材来源**。
这是流水线的地基——地基打歪了，后面六个阶段跑得再顺也是废稿。

**为什么目标读者排在角度前面**：没有具体的人，就没有对象感；没有对象感，就想象不出他们的问题和痛点；想象不出痛点，靶子、锚点、金句全是猜的。**罗胖体的每一招（你以为…其实…、开场场景、金句）都打在一个具体的人身上**。所以 S0 的硬产出是两张卡：**读者卡 + 选题卡**，读者卡在前。

**交互原则**：
- 用户已给齐素材 + 明确选题 → S0 压缩成一次快速确认（复述四要素，用户点头即过），**不要为了流程而流程**
- 用户只有模糊方向 → 给候选角度让他挑
- 用户完全没想法 → 先问，再给候选

---

## 一、三种进场姿势

### 姿势 A：用户带着素材和选题来
复述四要素让用户确认（半分钟），直接进 S1。候选角度环节跳过。**但读者卡不能省**——素材齐不等于对象清楚，"写给所有人"等于写给没有人。

### 姿势 B：用户只有一个大方向（如"写篇关于 GEO 的"）
做三件事：
1. 用一句话复述大方向，确认理解无误
2. 抛 **3–5 个候选角度**，每个角度必须绑定一个具体读者并压缩成反常识雏形：

```
角度 n：<一句大白话的说法>
  读者：<具体到可想象的一个人群，不要"从业者">
  反常识点：<他们>以为 A，其实 B
  他们的痛点：<一句话，越具体越好>
  一念判定：我想让<他们>相信：<一句话>
  需要的素材：<书/数据/亲历/案例，列 2–3 类>
  体裁倾向：短稿 / 长稿
```

注意：**同一个大方向，换一批读者就是一个新角度**。"GEO 该不该做"对老板和对执行者是完全不同的两篇稿。抛角度时把"读者"写在第一行，让用户先选人、再选说法。

3. 让用户挑一个或混搭，**当场定稿角度**，不要"回头再说"

### 姿势 C：用户完全没想法
先问三个问题（一次问完，不要挤牙膏）：
1. 这篇写给谁看？——逼他说到**具体的人**："上个月来找你问这件事的那个人，他是什么身份？"
2. 最近哪件事让你觉得"不对劲"或"跟大家想的不一样"？
3. 手头有什么可用的东西？（自己的经历 / 数据 / 书 / 一篇让你有情绪的文章）

拿到回答后按姿势 B 给候选角度。

---

## 二、读者卡（S0 的第一硬产出）

"写给谁"必须具体到**能想象出他此刻的处境**。"职业院校学生""中小企业主"都太粗，"被安排去做 AI 搜索优化的市场专员，老板下周要看效果"才合格。

```markdown
## 读者卡
- 一句话画像：<身份 + 处境，如"工作 3–5 年、刚被派去管 AI 项目的市场中层">
- 他此刻的场景：<具体到时间地点动作，如"周一早会前 10 分钟，老板问进展，他答不上来">
- 他的痛点（1–3 条）：<不是"焦虑"，是"汇报没东西可讲"；每条要能对应稿子里的一个段落>
- 他现有的错误认知：<他以为 X——这行直接成为稿子的靶子 X>
- 他渴望的结果：<Y——这行直接成为金句的落点>
- 他的语言：<他会怎么形容这件事？用他的词，不用行业黑话>
- 他读完会转发给谁：<检验这篇稿有没有"社交货币"属性>
```

**读者卡的三条验收线**：
1. **闭眼能看见**：读完画像，能想象出他此刻在哪个房间、愁什么。
2. **痛点有场景**：每条痛点都能讲成一个 10 秒的小场景，讲不出 = 太抽象，重写。
3. **错误认知成靶**：读者卡第 4 行能直接填进"你以为 X，其实 Y"——填不进去说明角度和读者错配，回角度环节重选。

读者卡一经确认，**贯穿 S1–S6 不可更换**：S1 的一念判定、S2 的靶子与金句、S3 的开场场景、S5 的审读视角，全部以这张卡为准。

## 三、角度质量红线

候选角度必须过三条线，过不了就换：

| 红线 | 判据 | 不过的表现 |
|---|---|---|
| **够反** | **这一批读者**里的聪明人会本能反驳它 | "终身学习很重要"式废话 |
| **有锚** | 能想到至少一类具象锚（书/人/数据/事件），且锚点最好出现在读者的世界里 | 只能抽象论证 |
| **有素材路径** | 用户能给，或公开来源可查，或明确标注"待搜集" | 全靠空想 |

**抛角度时就把素材来源写清楚**——这是"打基础"的核心：不是只定说法，而是定下"这篇的证据从哪来"。

## 四、素材来源清单（S0 必须落到纸面）

按可信度排序，逐项问用户"这个你能给吗 / 要我去查吗"：

1. **用户亲历**（最强：一段自己的经历、一次对话、一个决定）——优先要
2. **用户手头的一手数据**（业务数据、聊天记录、截图）
3. **书 / 文章**（用户在读的、或指定领域的一本）
4. **公开报道 / 论文 / 行业数据**（需用户授权后再搜集）
5. **本地名言库**（`~/Documents/githubprojects/quotes/public/quotes.json`，约 5400 条中文名言）——S2 挖借人金句时检索，默认可用
6. **本地书库**（`~/Downloads/reading/epub-md`，约 4500 本书的全文 md）——找"某本书里有个说法"，默认可用；单趟检索约 20 秒
7. **历史案例**（公开常识可兜底，标注"兜底"）

5、6 两库由 `scripts/search_quotes.py` 统一检索，产出只作候选，出处需复核。

素材来源要与读者卡对齐：**亲历和案例优先选与读者同行/同处境的**——读者看到"和我一样的人"才会往下读。

产出格式（读者卡 + 选题卡一并交付）：

```markdown
## 选题卡
- 读者卡：见上（或附后）
- 选题：<一句话>
- 角度：<反常识雏形>
- 一念判定：我想让<读者卡里的他>相信：____
- 体裁倾向：短稿 / 长稿 / 未定（S1 判）
- 素材来源：
  | 来源 | 内容 | 状态（已有 / 待用户提供 / 待搜集 / 兜底） |
- 缺口：<还差什么>
```

---

## 五、与用户收口

展示**读者卡 + 选题卡**，附三个一句话可改项：**换读者 / 换角度 / 换素材来源**（换读者排第一——它牵动最大）。
用户确认后进 S1。此闸门与 S3 大纲闸门是流水线仅有的两次人工介入。

**S0 的产出直接作为 S1 的输入**——S1 不再重新问选题，只做素材分类与核的确认。
