# 罗胖体写作

## 一句话范式

> 用一个"我刚发现"的笨人视角，把一条反常识结论，包装成「有出处 + 有场景 + 有金句」的最小故事。

他不生产知识，他生产**"你以为的答案是错的"这一瞬间**。全部技法都服务于制造并兑现这一个瞬间。

---

## 两个入口（先判断走哪条）

```
用户要什么？
│
├─ A. 从零产出一篇成稿（不管有没有给素材）
│     → 走流水线 S0–S6（见下）
│
└─ B. 只改已有文本 / 查风格规范 / 审风格
      → 不进流水线。直接用 references/style-core.md（精简规则）
        + references/patterns.md（完整词库与覆盖率）
        + 下文「改稿五步」
```

**判别句**：有"写一篇/写成稿"的动作 → A；只有"改/查/审" → B。

## 入口 A：流水线 S0–S6

```
S0 头脑风暴 ──⛔ 对话定选题/角度/素材 ──→ S1 素材梳理 ─→ S2 金句梳理 ─→ S3 大纲
                                                                              │
                                                              ⛔ 闸门：展示大纲，等确认
                                                                              ↓
                                              S6 定稿 ←─ S5 审核（机器+13项评分）←─ S4 初稿
```

| 阶段 | 干什么 | 参考文件 | 交互 |
|---|---|---|---|
| **S0 头脑风暴** | 与用户定**读者卡**（画像/场景/痛点/错误认知）+ 选题、角度、素材来源 | `references/stage-0-brainstorm.md` | ⛔ 对话 |
| **S1 素材梳理** | 素材六分类 → 三步筛选 → 找"核" → 一念判定 → 定体裁 | `references/stage-1-material.md` | 自动 |
| **S2 金句梳理** | 七问挖句（用户素材 + 两库召回 → **quote-miner 甄别**）→ 心坎测试 → 选定收口句 | `references/stage-2-golden.md` | 自动 |
| **S3 大纲** | 四拍卡 / 五段卡 / **舞台体卡**（靶子、场景、语言全部取自读者卡） | `references/stage-3-outline.md` | ⛔ 闸门 |
| **S4 初稿** | 逐段落盘、中途不回改 | `references/stage-4-draft.md` | 自动 |
| **S5 审核** | 脚本硬指标 + **critic subagent 13 项评分**（长稿再加 fact-checker） | `references/stage-5-review.md` | 自动 |
| **S6 定稿** | 吸收修改、朗读校准、只交成稿 | `references/stage-5-review.md` 末节 | 自动 |

**三种体裁**：短稿（60 秒四拍，**320–430 字**）/ 长稿（罗辑思维单集，≥3000 字，**语料中位 14.8k**）/ **舞台体（跨年演讲式：脆弱起头 + 发大愿、约 7 个编号话题、一句复诵 + 一个贯穿隐喻当 glue、祝福式收束）**。舞台体是独立骨架，不是"长一点的长稿"——用户说"演讲 / 发言 / 致辞 / 面对一群人讲"时走它，套五段卡上台会软。

**脚本只数数，判断交给 subagent**：`scripts/` 只做硬指标（字数、禁用语、人称/问号计数、编号、段落长度），**它判断不了质量**——实测一段通篇抽象、无真反转的空话稿能拿 95/100。凡是要读懂才能回答的（锚是不是真具象、反转到没到结构、金句成不成立、事实真伪、对象感），一律派 subagent。派发规范见 `agents/README.md`。

| 体裁 | S5 派谁 |
|---|---|
| 短稿 | **critic** |
| 长稿 | **critic ∥ fact-checker**（并行） |
| 舞台体 | **critic + reader**（不跑脚本） |
| S2 借句时 | **quote-miner** |

**对象感是全流水线的主线**：S0 的读者卡一经确认贯穿到底——S1 的一念判定、S2 的靶子与金句、S3 的开场与举例、S5 的审读视角都从它来。没有读者卡不准动笔；"写给所有人"等于写给没有人。

**交互边界**：只有 S0 和 S3 两处人工介入。S0 在"用户已给齐素材+选题"时压缩成半分钟确认；S1–S2、S4–S6 全自动不打扰。素材缺口尽量自行兜底（在素材卡标注"兜底"），只有"核"（反常识点）缺失时才向用户索取。

**工作目录约定**：S1 开工时建 `./.luopang-run/<选题短名>/`，素材卡（01）、金句表（02）、大纲（03）、草稿（04）、审核记录（05）全部落盘在此。**最终成稿复制到用户工作区交付，中间产物不主动展示**，用户追问"为什么这么写"时从这里调出。

### 各阶段要点（细节以参考文件为准）

- **S0**：三种进场姿势（带素材来 / 只有方向 / 完全没想法）。硬产出两张卡：**读者卡在前，选题卡在后**——读者卡要具体到"闭眼能看见他此刻的处境"，其"错误认知"行直接成为稿子的靶子。角度三红线：够反、有锚、有素材路径。
- **S1**：素材切最小颗粒，六类打标签（事实/数据锚、引语锚、书/文章锚、场景/轶事锚、反常识点、亲历）。素材是 URL 先抓正文再分类。逐条找"这批读者会觉得反"的点，最反的那条是核。压出「我想让**他**相信：____」，压不成一句 = 素材太散，砍或拆。体裁判定优先级：用户显式指定 > 选题卡倾向 > 规则（一个念头能说清 → 短稿 **320–430 字**，>550 会被脚本判 FAIL；要推翻读者现有认知、素材 ≥5 条跨领域 → 长稿 **≥3000 字**，语料中位 14.8k，**3000 只是下限不是目标**；现场对一群人讲 → **舞台体**）> 默认短稿。全流程只判一次，S3 选模板、S5 传 `--form` 都以它为准。
- **S2**：金句三个来源——①用户素材（首选）②本地名言库 quotes.json（约 5400 条）③本地书库 epub-md（约 4500 本）。两库用 `python3 scripts/search_quotes.py "关键词"` 一次**召回**（关键词取一念判定 + 读者卡的语言）。**召回 ≠ 可用**：脚本只会按关键词捞，混着叙事句和伪名言，必须派 **quote-miner**（`agents/quote-miner.md`）甄别，或自己逐条过四条硬标准（**≤30 字、有反转或对照、脱离上下文能单独成立、过心坎测试**）；引用保真——中文原句逐字引用标作者，英文原句只转述并注明书名；出处核不实就不借；外部借句一篇 ≤2 条。**先有金句，后有稿子。**
- **S3**：写完大纲立即停下展示，附三个一句话可改项（换读者/换核/换收），最多两轮。大纲每拍/每幕都要能对应读者卡的一条痛点。舞台体走 `stage-3-outline.md` 第三节的独立卡。
- **S4**：逐段写、逐段落盘，中途不回改；问题记进待改清单留给 S5。
- **S5**：两层审核。①脚本硬指标（FAIL=0 才过，最多 3 轮）；②派 **critic subagent** 做 13 项评分（≥21/26）。**脚本分高不代表稿子好**，质量判断以 critic 为准。第 1 项「对象感」一票否决，得 0 分不看总分直接退回 S0；长稿并行再派 fact-checker；舞台体不跑脚本，只派 critic + reader。
- **S6**：吸收全部修改、重跑脚本、朗读校准。交付一份 Markdown 成稿，按内容命名。

---

### S5 第一层：脚本硬指标（必跑）

```bash
python3 scripts/check_draft.py <草稿路径> --form short|long
```

`--form` **必填**，取 S1 的体裁判定——不要依赖 auto（auto 按字数猜，短稿写超会被用错检查集）。

脚本只验**数得清的硬指标**：体量、禁用语（综上所述 / 罗胖曰 / 众所周知 / 让我们一起 / 随着…的发展）、人称与问号计数、四拍编号、段落呼吸感。退出码 0 = 可进第二层。本脚本仅支持中文稿。

> ⚠️ **脚本不判断质量。** 开场锚是否真具象、转折是否到结构、有无大反转、是不是造词、结尾是不是 recap——这些它只能报**信号**（INFO，不进分数），真假由 critic subagent 判。实测空话稿能拿 95/100，别拿脚本分当合格证。

### S5 第二层：派 subagent（必派）

脚本 FAIL=0 之后，**必须派 critic**，不能自己审自己的稿。

```
派发 critic（agents/critic.md）需给：草稿绝对路径、读者卡绝对路径、体裁、
                                   脚本 --json 输出、评分表位置
长稿追加：fact-checker（可与 critic 并行）
舞台体追加：reader
```

派发硬规矩（详见 `agents/README.md`）：给绝对路径 · 带验收标准 · **只准写 `<scratch>/` 下指定文件，不准改草稿** · 发现缺口只报告不代补 · **空返回或超时要显式标注"降级为自审"，绝不静默跳过**。

## 入口 B：改稿五步（把已有文本改成罗胖体）

输入可以是用户的一段话、一篇现成文章、一版 AI 腔初稿。

1. **找靶子**：原文里那句"大众常识"是什么？没有就替它造一个（"过去我们以为…"）。靶子立不住，改稿无从谈起。
2. **换锚**：把抽象开头砍掉，从原文素材里找一个具象锚（数字/书/人/场景）；原文实在没有，用"话说 + 一个公认场景"兜底并标注。
3. **显式转折**：在原文结论前插入「其实 / 但是 / 你看」，把那一跳喊出来。检查反转深度：只翻到"另一种观点"不够，要翻到机制/结构。
4. **换收口**：删掉原文的总结段，按 `references/stage-2-golden.md` 的五型造一句收口金句（≤30 字）。
5. **自检**：过 `references/style-core.md` 的禁用清单 + 自检清单；有脚本条件时跑 `python3 scripts/check_draft.py <改后稿> --form short|long`。

改稿保真原则：**只动结构，不替用户编造事实**。原文的事实性内容一条不增不改；缺锚、缺机制时向用户指出，而不是替他补。

## 常见失败模式

| 症状 | 根因 | 修法 |
|---|---|---|
| 稿子"没味道" | 核不够反 | 回 S0/S1 重找认知冲突点；大众都同意的观点撑不起罗胖体 |
| 金句像标语 | 平铺直叙 | 回 S2 强制套"不是…而是…"或"过去我们以为…其实…" |
| 长稿读着累 | 段落太长、每幕没钩 | 每幕末尾加小金句；段落压到 2–4 句 |
| 素材不够写 | 硬凑 | S0 就该发现；回 S0 补素材来源，或改判短稿 |
| 大纲被反复打回 | 闸门给了太多选择 | 只给三个备选，让用户一句话就能改 |
| 改稿后事实走样 | 替用户编了内容 | 只动结构不增事实；缺口指出来让用户补 |
| 短稿被判"超出 60 秒承载" | 素材量超过四拍承载 | 改判长稿，别硬压字数；或砍掉次要素材只留一个核 |
| 稿子要**上台讲**却软趴趴 | 套了短稿/长稿骨架 | 改判**舞台体**：脆弱起头 + 发大愿、约 7 个编号话题、一句复诵当 glue |
| 人称堆了一堆还是不像 | 把密度当配额硬塞"你" | 人称是密度不是指标（篇均 ≈ 8）；回去修对象感，先想清楚在跟谁说话 |
| 脚本 95 分但稿子很难看 | 把脚本分当质量证明 | 脚本只数硬指标。派 critic，看那 13 项 |
| 主模型自审越看越满意 | 自己写的稿自己辩护 | 必须派 critic——它没看过写作过程 |
| subagent 空返回被静默跳过 | 没写降级标注 | 空返回/超时一律显式标"降级为自审"，见 `agents/README.md` |
| reader 的回答像在捧场 | 派发时把一念判定也给了它 | 只给读者卡 + 稿子，泄露意图则测试作废，重派 |
